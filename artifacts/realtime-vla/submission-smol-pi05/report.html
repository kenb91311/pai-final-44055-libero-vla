SmolVLAとπ0.5による、ボウル移載タスクの比較

ロボットが画像と言語指示から行動列を生成し、黒いボウルをつかんで皿へ置く。LIBERO向けに調整済みの公開モデルを用い、本制作では追加学習せず、センサ・ROS 2・方策・シミュレータ内の制御を接続した。

π0.5・非同期・配置1の実行記録。各画像の左は外部カメラ、右は手首カメラ。成否はLIBEROの公式判定を使用。

目的と検証した仮説

推論中も制御周期を維持するシステムを構築し、モデルの処理時間と操作成功の関係を調べた。計画時は、小型SmolVLAの低遅延が非同期操作に有利と予想した。そこで、同じ課題・初期配置・行動実行数でπ0.5と比較した。

センサ・ROS・制御の接続と
計算資源の管理

外部・手首画像、ロボット自身の状態、言語指示をVLAへ入力する。モデルは相対位置3・姿勢3・グリッパ1の行動列を出力し、既存の操作空間制御器（OSC、位置・姿勢のPD制御）が関節トルクへ変換する。

行動列は複数時点の指令をまとめたもの（action chunk）。画像・自己状態と行動列は、実際にROSの別ノード間で送受信し、受信した値を使用する。物体の正解位置は評価器だけが使用する。

撮像を制御周期から分離

2カメラの同期描画は平均85.64msで、20Hzの制御予算50msを超えた。画像なしのシミュレータ更新は8.98msだったため、状態を複製するカメラプロセスへ描画を分離した。

取得時刻と待ち行列の管理

画像と自己状態を同じsnapshotから作り、取得時刻を保持する。カメラの待ち行列は長さ1、推論要求は同時に1件とし、古い観測の蓄積を抑えた。

ハードウェア・プロセス管理の実装

GPUモデルを1種類ずつ実行。RTC追加系列と推論内訳計測では、別実験とGPU利用を調整し、全体使用量も監視した。
CPU・メモリ推論側4スレッド、撮像側BLAS 1スレッド。ROSコンテナはCPU 2コア相当・メモリ2GiBへ制限した。
主比較のモデル最大割当SmolVLA 1.47GiB / π0.5 8.87GiB。PyTorchのモデルプロセス内の最大値で、描画・デスクトップ込みのGPU全体とは範囲が異なる。
指令が未着のとき位置・姿勢の差分をゼロとし、グリッパ指令のみ維持。相対移動指令を繰り返して移動を続けない。
低位制御は既存実装を再利用

LIBERO / robosuiteのOSCとグリッパ制御を用い、MuJoCoの接触物理へ反映した。独自IKの追加ではなく、認識から既存制御器までの接続と、非同期時の時刻・資源管理を工夫した。

同期・非同期実行の比較

同期（lockstep）は推論中にシミュレーション時間を止める。非同期（realtime）は推論中も実経過時間に合わせ、50msごとに制御と物理演算を進める。

同期
10行動を実行推論中は物理進行を停止次の10行動
非同期・主比較
10行動を実行推論中も待機指令で物理を更新到着後に実行

概念図。帯の長さは実測時間を表さない。主比較では先読みせず、行動列を使い切ってから次を要求する。

共通条件と評価時間

両モデルとも生成50行動・flow反復10回。先頭10行動を実行し、同じ配置1〜5・乱数を使用した。同期は最大280制御step（14シミュレーション秒）、非同期は最大14実秒または280step。重み読込み・準備運転2回・初回行動列の生成は計時外とした。

観測から実行までの遅れ

通常指令の観測取得→実行は、SmolVLA約938ms、π0.5約812ms。π0.5も待機44.5%を含み、20Hzの制御維持と新指令の連続供給は別の指標である。

比較の範囲

同期は両者5/5、成功数の差は非同期で確認された。方式間は撮像の更新位相も異なるため、差を推論遅延だけの効果と断定しない。各5配置であり、一般的な性能順位とは扱わない。

計画時の速度予想と実測の違い

この課題・実装では、π0.5は非同期の成功数が多く、方策生成・出力処理も短かった。モデル規模だけでは説明できないため、同じ保存観測を用いた追加計測で処理区間を分けた。

画像処理とflow生成の比較

内部画像はSmolVLA 512×512、π0.5 224×224だが、画像エンコーダは約18〜19msだった。一方、flow生成は約498 / 231msであり、大きな差はこの区間に確認できた。行動expertは32層 / 18層で、幅やattention方式も異なる。繰り返す部分の構造は速度を考える手掛かりになるが、個別の寄与を分ける対照実験は未実施である。

精度と測定範囲を確認して解釈

代表的な行動expertのq_proj出力は両者BF16だった。SmolVLAを一律FP32とする説明は採用しない。区間計測の有無で両者の出力は完全一致した。前ページの508 / 332msは入力前処理を除く。計測範囲に加え並行負荷・準備運転も異なるため、この表を前ページの内訳としては扱わない。

行動列の接続を改善する検証

非同期生成では、新しい行動列が実行中の列と異なる動作を選ぶ場合がある。RTC（Real-Time Chunking）は、既存の予定指令と整合するよう生成中の行動変数を補正し、列の切り替えを滑らかにするための手法である。

既存の実行履歴・予定指令
→
遅れに合わせて生成中の列を補正
→
経過した指令を除いて切替

接続手法は別条件で比較した。生成50行動を保持し、残り30行動で次の推論を開始する（H50/R30）。同じモデル内で初期センサと最初の出力を照合し、補正なし・LeRobot公開RTC・生成中の行動変数への微分を追加した版を各5配置で評価した。重みは固定し、学習は行わない。

GPU使用を調整した再評価系列、計30試行。時間は初回を除く各試行平均の平均、待機は全tick合算。主比較の10行動・先読みなしとは待ち行列の条件が異なる。

切替時の指令差と、タスク成功を分けて評価

SmolVLAの公開RTCでは、同じ時点の旧予定と新採用の位置指令差が平均0.951→0.00869へ減少した。ただし成功は1/5のままだった。入力微分追加版は計算時間が増え、SmolVLAでは待機も22.35%へ増加した。π0.5は補正なし5/5に対し、RTCは両版4/5であり、成功数の改善は確認できなかった。

指令差はOSCの正規化位置指令のL2差（57 / 58切替）。メートル単位の位置誤差や、隣接する制御周期間の動作変化ではない。

モデルの速度予想総時間に加え、同一観測で視覚・VLM prefix・flowを分けて計測。小型モデルが常に速いとは限らず、今回の差は行動生成区間に集中した。
行動列の不連続先読みの条件を固定した対照を置き、RTCの指令差と成否を別に評価。指令の滑らかさ・待機短縮だけでは、把持・移載の成功は増えなかった。
通信のまれな待ちA2C2追加検証では最終指令のROS往復を別プロセス化。期限と指令IDを検査。通常の通信速度と遅い応答を区別。未着時は受信済み基盤指令へ戻した。
